# 计算机体系结构

> "计算机体系结构的本质，是在物理极限与人类可管理的复杂度之间寻找折中。" —— 亨利·科尔韦尔

计算机体系结构是连接软件与硬件的契约。自冯·诺依曼以"存储程序"一统计算之核，经流水线与缓存将性能推向单核极限，再到多核、GPU 与领域专用架构（DSA）打开并行之门——这条脉络既是摩尔定律的注脚，也是它的墓志铭。本文以六节贯通从指令到 IO、从经典到新兴的硬件全景。

---

## 一、冯·诺依曼架构与指令集

### 1.1 概念动机

早期的计算机如 ENIAC，靠手动接线与开关来"编程"——每解一题须重连数千线缆。冯·诺依曼在 1945 年的《EDVAC 报告》中提出一个革命性的简化：**程序与数据同存于存储器**，机器自行读取并执行。这便是"存储程序"概念，它将"编程"从物理操作降为信息搬运，使通用计算成为可能。

### 1.2 核心原理

冯·诺依曼架构以**存储程序**为纲，将计算机分为五大部件：

| 部件 | 职能 | 备注 |
|------|------|------|
| 运算器（ALU） | 执行算术与逻辑运算 | Arithmetic Logic Unit |
| 控制器（CU） | 取指、译码、协调各部件 | Control Unit |
| 存储器 | 存放程序与数据 | 统一编址 |
| 输入设备 | 将外部信息转为数据 | 键盘、传感器 |
| 输出设备 | 将计算结果外显 | 显示、打印 |

其中运算器与控制器合称**中央处理器（CPU）**。冯·诺依曼瓶颈在于：指令与数据共享同一总线，CPU 与内存间的通道成为吞吐瓶颈——这一缺陷催生了哈佛架构（分离指令与数据存储）与后来的缓存层次。

### 1.3 指令周期：取指—译码—执行

每条指令的执行遵循三个基本阶段，常细分为五步：

| 阶段 | 英文 | 动作 |
|------|------|------|
| 取指 | Fetch | 按 PC 从内存取指令至 IR |
| 译码 | Decode | 解析操作码与操作数，读寄存器 |
| 执行 | Execute | ALU 运算或访存 |
| 访存 | Memory | 读写数据存储器（可选） |
| 写回 | Write-back | 结果写回寄存器 |

程序计数器（PC）在取指后自增，跳转指令则改写 PC——控制流的本质即是对 PC 的重定向。

### 1.4 技术细节：RISC vs CISC

指令集架构（ISA）是软硬件的接口。两大流派之争贯穿数十年：

| 维度 | RISC（精简指令集） | CISC（复杂指令集） |
|------|--------------------|--------------------|
| 指令长度 | 定长，通常 4 字节 | 变长，1–15 字节 |
| 指令数 | 少，仅基础操作 | 多，含复杂复合操作 |
| 寻址模式 | 少，load/store 架构 | 多，内存直接运算 |
| 寄存器 | 多，编译器调度 | 相对少 |
| 硬件复杂度 | 低，利于流水线 | 高，微码译码 |
| 代表 | ARM、MIPS、RISC-V | x86 |

现代 x86 表面是 CISC，内部先将变长指令译为定长**微操作（μop）**，再以 RISC 风格的内核执行——可谓"外 CISC 内 RISC"的融合。而 ARM 与 RISC-V 凭借低功耗与开放授权，主导了移动与嵌入式领域。

### 1.5 实际应用

- **桌面与服务器**：x86-64 长期主导，Intel 与 AMD 分庭抗礼
- **移动与物联网**：ARM 架构占据 99% 智能手机市场
- **开放生态**：RISC-V 以免费指令集撬动国产芯片与定制加速器

## 二、CPU 流水线与超标量

### 2.1 概念动机

单条指令的执行若串行进行，取指时 ALU 空闲，执行时存储器闲置——资源利用率低下。流水线的灵感来自工厂装配线：将指令周期分为若干级，各级并行处理不同指令，使吞吐率逼近单级时钟频率的倒数。这是单核性能提升的第一根杠杆。

### 2.2 五级流水线

经典 RISC 五级流水线如下，每级对应一个时钟周期：

| 级 | 缩写 | 功能 |
|----|------|------|
| 取指 | IF（Instruction Fetch） | 从指令缓存取指令 |
| 译码 | ID（Instruction Decode） | 译码、读寄存器堆 |
| 执行 | EX（Execute） | ALU 运算、分支判定 |
| 访存 | MEM（Memory Access） | load/store 数据缓存 |
| 写回 | WB（Write Back） | 结果写回寄存器 |

理想情况下，$N$ 级流水线可使吞吐率提升 $N$ 倍。然而指令间的依赖会破坏这一理想。

### 2.3 技术细节：流水线冒险

三类冒险（hazard）威胁流水线效率：

| 冒险类型 | 成因 | 典型对策 |
|----------|------|----------|
| 数据冒险 | 后指令依赖前指令结果 | 转发（forwarding）、停顿（stall） |
| 控制冒险 | 分支跳转改变流向 | 分支预测、延迟分支 |
| 结构冒险 | 同一周期争用硬件资源 | 资源复制、哈佛结构 |

数据冒险细分为 RAW（写后读，真依赖）、WAW（写后写）、WAR（读后写）。转发的关键在于：ALU 结果不必等写回，可直接旁路给下一指令的输入端。

### 2.4 分支预测与投机

条件分支使取指方向不明，预测错误须冲刷流水线。现代 CPU 采用两级预测：

- **分支目标缓冲（BTB）**：记录历史跳转地址
- **模式历史表（PHT）**：基于两位饱和计数器预测"跳/不跳"
- **高级**：锦标赛预测器、感知机预测器，准确率可达 97%+

**投机执行（speculation）**：CPU 按预测方向先行执行，待条件确定后提交（commit）或回滚。2018 年的 Spectre 漏洞正是利用投机执行的副作用泄露数据——性能与安全的张力由此凸显。

### 2.5 超标量与乱序执行

超标量（superscalar）指每周期发射多条指令，依赖硬件动态调度。乱序执行（Out-of-Order, OoO）打破程序顺序，按数据就绪重排执行，再于提交阶段恢复程序语义：

1. **取指译码** → 拆为 μop 入队
2. **重命名**：消除假依赖（WAW、WAR），将 architectural register 映射到物理寄存器
3. **发射**：μop 等待操作数就绪后送入执行端口
4. **执行**：多个 ALU/访存单元并行
5. **重排序缓冲（ROB）**：按程序顺序提交，保证精确异常

### 2.6 SIMD 指令

单指令多数据（SIMD）以一条指令并行处理多个数据 lane，适合图像、音视频与矩阵运算：

| 指令集 | 位宽 | 厂商 |
|--------|------|------|
| SSE / AVX / AVX-512 | 128/256/512 bit | Intel x86 |
| NEON | 128 bit | ARM |
| SVE / SVE2 | 可变长 | ARM |
| RVV | 可变长 | RISC-V |

### 2.7 实际应用

- **游戏与渲染**：超标量与 SIMD 共同支撑每帧数十亿次浮点运算
- **数据库引擎**：乱序执行隐藏访存延迟，提升 OLTP 吞吐
- **安全警示**：投机执行漏洞（Spectre/Meltdown）迫使操作系统与微码大改

## 三、存储器层次

### 3.1 概念动机

存储技术的"不可能三角"：速度快则贵、容量大则慢、便宜则断电易失。没有单一介质能同时满足速度、容量与成本。体系结构的解法是**层次结构**——以小而快的存储藏匿于 CPU 侧，大而慢者居外，靠局部性原理使多数访问命中高速层。

### 3.2 核心原理：存储层次表

| 层级 | 介质 | 典型容量 | 访问延迟 | 是否易失 |
|------|------|----------|----------|----------|
| 寄存器 | SRAM 触发器 | 数十至数百个 | <1 ns | 是 |
| L1 缓存 | SRAM | 32–64 KB | ~1 ns | 是 |
| L2 缓存 | SRAM | 256 KB–1 MB | 3–10 ns | 是 |
| L3 缓存 | SRAM（共享） | 8–64 MB | 10–30 ns | 是 |
| 主存 | DRAM | 8–256 GB | 50–100 ns | 是 |
| SSD | NAND Flash | 256 GB–4 TB | 10–100 μs | 否 |
| HDD | 磁盘 | 1–20 TB | 5–10 ms | 否 |

从寄存器到 HDD，延迟跨越约八个数量级——层次结构的目标是让平均访问时间逼近最快一级。

### 3.3 技术细节：局部性原理

局部性是缓存有效的统计学基础：

- **时间局部性**：刚被访问的数据近期很可能再被访问（循环变量、栈顶）
- **空间局部性**：地址相邻的数据倾向于被一并访问（数组顺序遍历、指令顺序执行）

缓存行（cache line，通常 64 字节）一次搬运一整块，正是为利用空间局部性。

### 3.4 缓存映射方式

主存块如何映射到缓存行，决定了命中率与硬件成本：

| 映射方式 | 映射规则 | 优点 | 缺点 |
|----------|----------|------|------|
| 直接映射 | 块号 mod 缓存行数 | 硬件简单、速度快 | 冲突率高 |
| 组相联 | 组内任意行 | 冲突与复杂度折中 | 主流选择（N 路） |
| 全相联 | 任意位置 | 冲突最低 | 比较器多、功耗高 |

L1 常用 8 路组相联，L3 可达 16 路。缓存地址解析为：`Tag | Set Index | Block Offset`。

### 3.5 写策略

数据写入时，缓存与下一级的一致性如何维护：

| 策略 | 行为 | 特点 |
|------|------|------|
| 写直达（write-through） | 同时写缓存与下层 | 简单、一致，但写慢 |
| 写回（write-back） | 仅写缓存，置脏位，替换时回写 | 快，但需维护一致性 |
| 写分配（write-allocate） | 写缺失时先调入块再写 | 配合写回 |
| 不写分配（no-write-allocate） | 写缺失直写下层 | 配合写直达 |

多核场景下，缓存一致性协议（如 MESI）保证各核所见主存值一致——这是共享内存并行的硬件基石。

### 3.6 虚拟内存与 TLB

虚拟内存以页表将逻辑地址映射到物理地址，使每进程拥有独立连续的地址空间。然而每次访存须查多级页表，开销可观。**旁路转换缓冲（TLB）** 是页表项的缓存，缓存最近虚拟页到物理页的映射：

- 典型 L1 TLB：64–128 项，命中延迟 1 周期
- 缺失代价：数十至上百周期（需硬件 page table walker）
- 大页（2 MB / 1 GB）减少页表项数，降低 TLB 压力

### 3.7 实际应用

- **数据库**：精心布局数据以利用缓存行与预取
- **高性能计算**：分块（blocking/tiling）矩阵乘法，使工作集落入 L2
- **大内存应用**：透明大页（THP）降低 TLB 缺失，提升长期吞吐

## 四、并行计算

### 4.1 概念动机

单核频率受功耗墙与频率墙双重夹击，摩尔定律的红利从"提频"转向"加核"。并行计算从可选优化升格为继续提升性能的必由之路。然并行并非免费午餐——它引入了同步、通信与一致性等根本性开销。

### 4.2 Flynn 分类法

按指令流与数据流的数量，并行计算机分为四类：

| 类型 | 指令流 | 数据流 | 代表 |
|------|--------|--------|------|
| SISD | 单 | 单 | 标量 CPU |
| SIMD | 单 | 多 | GPU、向量机 |
| MISD | 多 | 单 | 罕见（容错系统） |
| MIMD | 多 | 多 | 多核、集群 |

现代 CPU 是 SISD+SIMD 混合，GPU 是 SIMD 的海量扩展，集群是 MIMD 的分布式实例。

### 4.3 共享内存与分布式内存

| 模型 | 内存视图 | 通信方式 | 代表架构 |
|------|----------|----------|----------|
| 共享内存（UMA） | 全局统一 | load/store | 对称多处理（SMP） |
| 共享内存（NUMA） | 统一但分片 | load/store，跨片慢 | 多路服务器 |
| 分布式内存 | 各结点私有 | 消息传递（MPI） | 超算集群 |

NUMA（非统一内存访问）下，访问本地内存快于远端——操作系统须做 NUMA 感知的调度与内存分配。

### 4.4 多核架构

多核将多个处理器核集成于同一封装，共享 L3 缓存与内存控制器：

- **同构多核**：核间能力对等（如 8 核 x86）
- **异构多核**：大小核混搭（ARM big.LITTLE、Intel P+E core）
- **片上互联**：Ring Bus、Mesh、NoC 决定核间延迟

核数增长带来的并行加速受**串行部分**制约——这便是 Amdahl 定律。

### 4.5 Amdahl 定律与 Gustafson 定律

**Amdahl 定律**：设程序中串行占比为 $s$，则 $N$ 核加速比上限为

$$
S_{\max} = \frac{1}{s + \frac{1-s}{N}}
$$

当 $N \to \infty$，$S \to 1/s$——串行部分是天花板。这一定律对固定问题规模持悲观态度。

**Gustafson 定律**：若问题规模随核数增长（并行部分扩大），则加速比为

$$
S = N - s(N-1)
$$

即近乎线性——这一定律对可扩展工作负载持乐观态度。二者的差异在于对"问题规模是否固定"的假设。

### 4.6 GPU 架构与 CUDA

GPU 是面向吞吐的 SIMD 处理器，以数千核心并行处理图形与通用计算。NVIDIA 的编程模型：

| 概念 | 含义 |
|------|------|
| Thread | 最小执行单元 |
| Warp | 32 线程为一组，SIMT 调度 |
| Block | 线程块，共享内存与同步 |
| Grid | 网格，跨 block 独立调度 |

- **SIMT（单指令多线程）**：硬件自动管理线程束，比手动 SIMD 更灵活
- **共享内存**：block 内高速 SRAM，需显式管理
- **全局内存**：DRAM，带宽高但延迟大，须以合并访存（coalesced）优化

AMD 的 ROCm/HIP 与 CUDA 模型相近，SYL/OpenCL 则试图跨厂商统一。

### 4.7 实际应用

- **科学计算**：TOP500 超算以 GPU+CPU 异构架构登顶
- **深度学习**：GPU 的矩阵乘法吞吐是训练神经网络的主力
- **大数据**：Spark、Flink 以分布式内存模型处理海量数据

## 五、IO 系统与总线

### 5.1 概念动机

CPU 与内存再快，若无 IO 与外界交互，计算机只是自闭的计算器。IO 系统的使命是在高速的内部总线与低速、多样的外设之间架设桥梁——既要保证数据正确传输，又要尽量不让 CPU 在等待中空转。

### 5.2 总线分类

总线是共享的信号通道，按职能分为三类：

| 总线类型 | 承载 | 典型宽度 |
|----------|------|----------|
| 数据总线 | 读写数据 | 32/64/128 bit |
| 地址总线 | 指定内存/端口地址 | 32/64 bit |
| 控制总线 | 时钟、读/写、中断、复位等控制信号 | 若干 |

现代系统多以**点对点链路**（如 PCIe、HyperTransport）取代共享总线，但"总线"一词仍作为逻辑概念沿用。

### 5.3 IO 传输方式

| 方式 | CPU 介入 | 特点 |
|------|----------|------|
| 轮询（polling） | 持续查询状态 | 简单但 CPU 占用高 |
| 中断驱动 | 设备就绪触发中断 | CPU 可并行工作，切换有开销 |
| DMA | DMA 控制器直传内存 | 大块传输不占 CPU |
| 通道（channel） | 专用 IO 处理器 | 大型机常见 |

DMA（直接内存访问）是大批量传输的关键：CPU 仅设置描述符（地址、长度、方向），DMA 控制器接管总线周期完成搬运，结束后以中断通知。

### 5.4 磁盘调度算法

机械硬盘的寻道是性能瓶颈，调度算法旨在减少磁头移动：

| 算法 | 策略 | 特点 |
|------|------|------|
| FCFS | 按请求顺序服务 | 公平但寻道长 |
| SSTF | 选最近磁道 | 高吞吐但可能饥饿 |
| SCAN | 电梯式单向扫描到端 | 公平、无饥饿 |
| C-SCAN | 单向扫描，到端回起点 | 均匀等待时间 |
| LOOK | 扫描至最远请求即回 | 不必走到物理端 |

SSD 无机械结构，调度算法影响较小，但仍可优化并行单元与垃圾回收。

### 5.5 RAID 级别

独立磁盘冗余阵列以多盘组合换取性能与可靠：

| 级别 | 结构 | 冗余 | 最少盘数 | 特点 |
|------|------|------|----------|------|
| RAID 0 | 条带 | 无 | 2 | 速度最快，无容错 |
| RAID 1 | 镜像 | 全复制 | 2 | 读快写慢，容错高 |
| RAID 2 | 位级汉明码 | 校验 | 3+ | 已淘汰 |
| RAID 3 | 字节级条带 + 专用校验 | 1 盘 | 3+ | 单盘容错 |
| RAID 4 | 块级条带 + 专用校验 | 1 盘 | 3+ | 校验盘瓶颈 |
| RAID 5 | 块级条带 + 分布校验 | 1 盘 | 3+ | 主流，平衡 |
| RAID 6 | 双分布校验 | 2 盘 | 4+ | 可容两盘失效 |

实际工程多采嵌套组合，如 RAID 10（镜像+条带）兼顾性能与安全。

### 5.6 NVMe 与 PCIe

| 接口 | 协议 | 延迟 | 队列深度 |
|------|------|------|----------|
| SATA AHCI | SCSI 风格 | ~100 μs | 1 队列/32 深 |
| NVMe over PCIe | 多队列并行 | ~10 μs | 64K 队列 × 64K 深 |

NVMe 专为闪存设计，绕过 AHCI 的单队列瓶颈，配合 PCIe 4.0/5.0 通道可达 7+ GB/s 读写——是现代存储的标配。

### 5.7 实际应用

- **数据中心**：NVMe SSD + RAID 构建高 IOPS 存储集群
- **消费电子**：UFS/eMMC 是手机的 IO 主力
- **外设互联**：USB、Thunderbolt 覆盖热插拔与高速外设

## 六、新兴架构趋势

### 6.1 概念动机

通用 CPU 追求"什么都能做"，却在特定负载上效率低下——以万亿晶体管跑标量代码，如同用万用刀雕玉。摩尔定律趋缓、功耗墙逼近之际，"专用化"成为新的性能来源。领域专用架构（DSA）与计算范式革新，正在重塑硬件的版图。

### 6.2 领域专用架构（DSA）

DSA 针对特定工作负载定制数据通路，以面积与能换取吞吐：

- 去除不用的功能（分支预测、乱序），简化控制
- 定制数据类型（BF16、INT8、FP8）
- 专用存储层次与互连

Google TPU 是典范：以**脉动阵列（systolic array）**执行矩阵乘法，数据从一端流入、经二维计算单元阵列、结果从另一端流出——每个周期全阵列并行，能效远超 GPU。

### 6.3 神经形态计算

模仿生物神经元的脉冲计算模型：

- **脉冲神经网络（SNN）**：以事件驱动的脉冲传递信息，稀疏且异步
- **忆阻器（memristor）**：阻值记忆，可模拟突触权重
- 代表芯片：Intel Loihi、IBM TrueNorth

特点是极低功耗与时序编码，适合边缘感知与实时信号处理，但训练算法与工具链尚不成熟。

### 6.4 量子计算基础

量子计算以量子力学现象扩展计算模型：

| 概念 | 含义 |
|------|------|
| 量子比特（qubit） | 可处于 $|0\rangle$ 与 $|1\rangle$ 的叠加 |
| 叠加（superposition） | $|\psi\rangle = \alpha|0\rangle + \beta|1\rangle$，测量塌缩 |
| 纠缠（entanglement） | 多比特状态不可分离 |
| 量子门 | 作用于比特的酉变换，如 Hadamard、CNOT |

$n$ 个 qubit 可表示 $2^n$ 个状态的叠加，Shor 算法可在多项式时间分解大数——对 RSA 构成根本威胁。然量子比特易受退相干，纠错需大量物理比特编码一个逻辑比特，工程挑战巨大。

### 6.5 光计算

以光子替代电子承载计算：

- **光互连**：低能耗高带宽的片间/片上通信
- **光神经网络**：利用马赫-曾德干涉仪实现矩阵乘法
- 优势：并行度高、能耗低、延迟小
- 劣势：器件体积大、非线性难实现、可编程性弱

### 6.6 存算一体与近存计算

传统架构中，数据须在存储与计算间往返，"存储墙"能耗远超计算本身：

| 方案 | 思路 | 优势 | 挑战 |
|------|------|------|------|
| 存算一体（PIM） | 在存储阵列内直接计算 | 消除搬运，能效极高 | 工艺难、精度低、通用性弱 |
| 近存计算（NDP） | 计算单元紧贴存储 | 减少访存延迟 | 编程模型需重塑 |

PIM 基于 SRAM/RRAM/DRAM 的模拟计算特性，适合低精度高吞吐的推理场景；NDP 则在 HBM 旁堆叠逻辑裸片，是 AI 加速器的热门方向。

### 6.7 实际应用与展望

- **AI 推理**：TPU、华为昇腾、寒武纪均以脉动阵列或类 DSA 提升能效
- **科学计算**：量子计算有望破解经典难解的化学模拟与组合优化
- **边缘智能**：神经形态与 PIM 赋能超低功耗的常驻感知设备

体系结构的未来不再是"一种架构走天下"，而是**通用 CPU + 专用加速器**的异构共生——硬件的多样性，映射着计算需求的多样性。
